PROJECT 02 ● Live
Roz Ka Commit (RKC)
DAILY GITHUB CONTRIBUTION TRACKER

"Aaj ka commit, kal ki progress."

  • Tracks real GitHub commits for a group and awards 10 points per active day, so it rewards consistency rather than commit count, with streaks and a live leaderboard (today / week / month / all time).
  • Dashboard with a GitHub-style contribution calendar, Chart.js weekly and monthly trends, and per-contributor details.
  • Scoring that can't be gamed: PostgreSQL triggers calculate points, unique constraints stop double counting, future-dated commits are rejected, and Row Level Security allows only admins to write.
  • Hourly GitHub → Supabase sync through GitHub Actions, triggered by cron-job.org, that handles API rate limits, retries and resumable syncs so no commit is missed.
  • Covered by 29 unit tests, database integration tests and Playwright end-to-end tests; hosted on GitHub Pages with Supabase.

PROJECT 03 ⬡ Personal
API Monitoring, Incident Management & Alerting System
BACKEND · MONITORING · AUTOMATION

A Flask-based web application that automates API health monitoring. It periodically checks registered endpoints, evaluates their responses, records incidents when something fails, and sends Discord alerts on both failure and recovery, so nobody has to check APIs by hand.

  • Automated health checks: APScheduler periodically sends HTTP requests to every registered endpoint, checking availability and measuring response times.
  • Response evaluation: classifies status codes (2xx success vs. 4xx/5xx failures) and connection errors to decide whether an API is healthy.
  • Incident lifecycle: failures automatically open an incident linked to the affected API in PostgreSQL; later checks detect recovery and mark it resolved.
  • Discord alerting: webhook notifications with API and failure details on every outage and every recovery.
  • Dashboard & history: web interface for registered APIs, monitoring status, active and resolved incidents, history and reports.
  • Modular backend: monitoring, incident and alert logic are separate services, which keeps the codebase maintainable and easy to extend.
